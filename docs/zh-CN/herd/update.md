# 保持 Herd 更新

已安装的 Herd 可以保持更新，**无需重新格式化**，也无需等待新的 ISO，并且使用的是与其他版本相同的已签名软件仓库。更新分为两种类型，使用不同的工具：

| 类型 | 变更内容 | 工具 |
|---|---|---|
| **日常更新** | 同一代系统内的修复和新软件包版本 | `dnf upgrade` |
| **跨代升级** | 升级到系统的下一代（新的 Fedora 基础系统） | `herd-upgrade` |

!!! note "本页面针对的是 Herd"
    桌面版使用 `capivaraos-upgrade`，并且确实会自动创建 Btrfs 快照。在 Herd 上这两点都不同，这正是本页面要说明的内容。关于桌面版，请参阅[保持系统更新](../update/index.md)。

## 日常更新

```bash
sudo dnf upgrade --refresh
```

除了 Fedora 的软件包之外，你还会从**已签名的软件仓库**中接收**我们的软件包**：每个软件包**以及**元数据都会使用我们的 GPG 密钥进行验证（`gpgcheck` + `repo_gpgcheck`）。如果签名验证不通过，**事务将会中止** —— 绝不存在绕过验证来安装我们软件包的途径。

## 跨代升级

`herd-upgrade` 通过明确的步骤执行 `dnf5 system-upgrade`：

```bash
herd-upgrade                   # 预检：显示将会发生什么；不更改任何内容
sudo herd-upgrade download     # 下载离线事务（不重启）
sudo herd-upgrade reboot       # 立即应用，重启进入离线模式
```

不带参数时，它会运行预检并且**不会更改任何内容**。默认目标是当前代 + 1；若要指定其他目标，请使用 `--to N`。

!!! tip "请先运行预检"
    预检会针对**你的**机器回答以下问题：目标代是否已发布、根目录位于什么文件系统上，以及是否会创建快照。你无需猜测自己处于哪种情况。

如果尚未发布目标代，预检会**拒绝**执行 —— 器将迁移到新的 Fedora 基础系统，而把 CapivaraOS 的专属软件包落下。这是正确的设计，而非故障。

## 快照与恢复

这是值得提前规划的部分。

常见的服务器布局是 **LVM + xfs**，在这种配置下**没有自动快照**：Snapper 仅支持 Btrfs，不支持 xfs。Herd 也**不会预装并配置 Snapper**。`herd-upgrade` 会检测具体情况，并在预检中告知你处于哪种情况：

- **根目录位于 LVM 上** —— 无自动快照。该工具会打印出需要手动执行的命令（`lvcreate -s …`），该命令依赖于**卷组中的可用空间**。在根分区被扩展至占满磁盘的安装环境中，没有空间可用于创建快照。
- **根目录位于 Btrfs 上且配置了活跃的 Snapper `root` 配置** —— 自动快照，与桌面版相同。这需要你自己安装并配置 Snapper。
- **均不属于以上情况** —— 不进行任何快照。

因此，在服务器上，**恢复途径就是你的备份**。在进行跨代升级前获取经过验证的备份，并将恢复该备份视为退路。

!!! warning "不要指望在 Herd 上进行快照回滚"
    快照回滚 —— 以及随之使用的 `lvconvert --merge` —— 仅在快照存在时才有效。在 Herd 的默认布局中，它是不存在的。请制定好备份计划。

### 另一种情况是内核无法启动

新内核启动失败不需要恢复任何数据。系统会保留**最近三个**已安装的内核版本（dnf 的默认行为），并且 GRUB 菜单允许你启动前一个版本。这涵盖的是内核变更，而不是跨代升级。
